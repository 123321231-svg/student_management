# 学生学业数据分析与管理平台升级设计

## 1. 背景与目标

本项目现有三个清晰阶段：

- `9c24386`：Python 与 SQLite 命令行稳定版，适合作为基础学习材料。
- `41255d3`：FastAPI 网页基础版，已经具备登录、权限、学生管理、搜索、图表和 Excel 导入导出。
- 本设计：在现有 FastAPI 版本之上，先发布易于理解的润色稳定版，再升级为面向数据分析开发和全栈实习的求职作品集版本。

目标用户是正在准备暑假实习的本科二年级学生。项目既要体现真实工程能力，也必须保持可学习、可解释、可在面试中独立讲清楚。

## 2. 成功标准

### 2.1 求职展示

- 招聘方可以在五分钟内从 README 理解项目解决的问题、主要功能和技术亮点。
- 项目展示 Python 后端、关系型数据库、数据分析、权限控制、自动测试、容器化和持续集成能力。
- 提供可运行源码、Docker 环境和 Windows 便携发布包。
- Git 历史清晰展示从命令行程序到工程化 Web 平台的演进过程。

### 2.2 学习体验

- 模块职责单一，避免大型文件同时承担路由、业务和数据库职责。
- 重要注释解释设计原因，不使用逐行翻译代码的低价值注释。
- 文档从 Python 基础知识逐步过渡到 FastAPI、SQLAlchemy、Pandas、测试和部署。
- 提供代码地图、阅读顺序、练习任务和面试问答。
- 不引入当前目标不需要的微服务、Redis、消息队列或复杂机器学习模型。

### 2.3 工程质量

- 核心业务测试覆盖率不低于 80%。
- GitHub Actions 自动执行测试、代码检查和 Windows 发布包构建。
- PostgreSQL 用于正式部署，SQLite 用于本地学习、测试和 EXE 版本。
- 数据库结构由 Alembic 管理，敏感配置仅通过环境变量注入。

## 4. 总体架构

```text
浏览器界面
Jinja2 + HTMX + Chart.js
        |
FastAPI 路由层
网页路由 + REST API /api/v1
        |
业务服务层
学生管理、成绩分析、导入、风险预警
        |
数据访问层
SQLAlchemy Repository
        |
PostgreSQL / SQLite
```

建议目录结构：

```text
app/
  main.py
  core/          # 配置、安全、异常和依赖
  db/            # 会话、模型、迁移和初始化
  auth/          # 登录、用户和角色权限
  students/      # 学生与班级业务
  academics/     # 课程、考试和成绩业务
  analytics/     # 指标、趋势、风险和数据质量
  imports/       # Excel 预检查、确认和错误报告
  audit/         # 审计日志
  api/v1/        # REST API 路由
  web/           # 网页路由、模板和静态资源
tests/
docs/
scripts/
```

每个业务模块由路由、Schema、Service 和 Repository 组成。路由只处理 HTTP 输入输出，Service 表达业务规则，Repository 封装数据库操作，分析模块只接收结构化数据并返回分析结果。

## 5. 数据模型

### 5.1 用户与权限

- `User`：用户名、姓名、密码哈希、角色、启用状态、创建时间。
- 角色固定为管理员、教师和只读用户。
- 管理员管理账号与角色；教师管理学业数据；只读用户只能查看和导出。

### 5.2 学业数据

- `ClassGroup`：年级、专业、班级名称。
- `Student`：学号、姓名、班级、联系方式、入学时间和状态。
- `Course`：课程编号、名称、学分和任课教师。
- `Assessment`：课程、考试名称、考试日期和满分。
- `Score`：学生、考试、原始分数和提交时间。
- `AuditLog`：操作人、动作、对象、详情和时间。

学号、课程编号以及学生与考试的成绩组合必须唯一。删除被引用的数据时优先使用停用状态或受控删除，避免破坏历史分析。

## 6. 核心业务功能

- 学生、班级、课程、考试和成绩的增删改查。
- 服务端分页、排序、关键字搜索和多条件筛选。
- Excel 模板下载、批量导入和筛选结果导出。
- 导入预检查识别重复学号、缺失字段、非法分数和不存在的关联数据。
- 用户确认后才写入数据库；失败行可下载为单独 Excel 报告。
- 所有关键创建、修改、删除、导入和角色调整写入审计日志。
- 健康检查接口用于 Docker、发布包和部署平台判断服务状态。

## 7. 数据分析设计

### 7.1 总览指标

- 学生数、班级数、课程数和考试数。
- 平均成绩、及格率、优秀率和风险学生数。
- 成绩区间分布、近期考试趋势和班级对比。

### 7.2 分析视角

- 班级分析：平均分、标准差、及格率、优秀率和课程差异。
- 课程分析：平均分、成绩离散程度、考试趋势和难度参考。
- 学生分析：历次考试趋势、课程雷达或对比、排名变化和风险原因。
- 数据质量：缺失字段、重复记录、异常分数和导入失败统计。

### 7.3 风险预警

第一版使用透明规则，不使用黑盒预测：

- 多次不及格。
- 连续考试成绩下降。
- 成绩显著低于所在班级平均值。
- 关键数据缺失导致分析不完整。

每条预警返回触发规则、相关数据和解释文本。阈值集中配置并有独立测试，便于学习、讨论和后续调整。

## 8. 网页与 API

网页使用 Jinja2、HTMX 和 Chart.js，不引入 React。主要页面包括：

- 总览仪表盘。
- 学生、班级、课程、考试和成绩管理。
- 数据导入预览与错误报告。
- 班级、课程和学生分析中心。
- 用户权限与审计日志。

REST API 使用 `/api/v1` 前缀，例如：

```text
GET    /api/v1/students
POST   /api/v1/students
GET    /api/v1/students/{id}
PATCH  /api/v1/students/{id}
DELETE /api/v1/students/{id}
GET    /api/v1/analytics/overview
GET    /api/v1/analytics/classes/{id}
GET    /api/v1/analytics/students/{id}/trend
POST   /api/v1/imports/scores/preview
POST   /api/v1/imports/scores/confirm
```

API 返回统一错误结构，并为列表接口提供分页元数据。OpenAPI 文档保留为后端能力展示入口。

## 9. 安全与错误处理

- 使用安全密码哈希和会话 Cookie。
- 网页写操作使用 CSRF 防护，API 使用可复用的权限依赖。
- 生产环境拒绝默认密钥和默认管理员密码。
- 防止管理员取消系统最后一个管理员，防止用户误删自己的管理账号。
- 上传文件限制扩展名、MIME 类型、大小和最大行数。
- 用户看到明确但不泄漏内部细节的错误提示；服务端记录必要诊断信息。
- 所有数据库写操作使用事务，导入失败时不留下半完成数据。

## 10. 测试与持续集成

开发遵循测试驱动流程：先写一个能正确失败的行为测试，再实现最少代码使其通过，最后重构。

测试范围包括：

- 密码、CSRF 和角色权限。
- 学生、课程、考试和成绩服务。
- 分页、筛选和重复约束。
- Excel 预检查、确认导入、错误报告和事务回滚。
- 各项分析指标及空数据、边界分数和异常数据。
- 风险规则及阈值边界。
- API 和关键网页流程。

GitHub Actions 执行 pytest、覆盖率和 Ruff。Windows 发布工作流在版本标签创建后构建发布包。

## 11. Windows EXE 与发布

- PyInstaller 构建 Windows 便携版本。
- 双击启动器后选择可用端口，启动 FastAPI 并自动打开浏览器。
- EXE 使用 SQLite，数据库保存在用户数据目录，程序升级不会覆盖数据。
- 模板、静态资源、演示数据和版本信息包含在发布包中。
- 启动器提供健康检查、重复启动检测和清晰的错误提示。
- GitHub Release 上传 `StudentAnalytics-v3.0.0-windows.zip`、校验文件和使用说明。

Docker/PostgreSQL 是正式工程版本，Windows EXE 是方便教师、同学和招聘方快速体验的便携版本，两者共享同一业务服务和测试。

## 14. 非目标

本轮不实现以下内容：

- 微服务拆分。
- Redis、消息队列或分布式任务。
- React/Vue 单页应用。
- 无明确数据依据的机器学习预测。
- 多租户计费、复杂通知系统或移动端原生应用。

这些能力可作为后续学习方向，但不应降低当前版本的完成度和可解释性。
